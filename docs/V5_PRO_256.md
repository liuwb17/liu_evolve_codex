# v5 Pro: extend the existing run to 256 total API requests

On 2026-09-25 the user requested the same settings as v5 Flash, changing only
the model. The existing problem-only cold-start lineage is continued, not reset.
All requests already used, including failures, count toward the total 256.
The v4 Pro experiment remains capped at 64 requests.

The development directory retains its historical name:
`runs/v5_pro_64_20260925`. The new terminal output directory is
`runs/v5_pro_256_system_1000_20260925`.

The extension stops the original controller after its current proposal completes.
`scripts/v5_pro_256.py` archives the old protocol, state, orchestration and ledger
in `budget_256_migration/`. It permits only `config.calls: 64 -> 256`, updates
the checkpoint signature with that authorized change, and verifies that the new
protocol equals the Flash protocol after replacing only `config.model` with
`deepseek-v4-pro`. Candidate sources, API response IDs, cached evaluations and
the ledger remain intact. Validation must not have begun.

Both v5 runs use the identical hashed engine/provider, thinking enabled with
low reasoning effort, 65,536 maximum output tokens, no aggregate token cap,
40 public training cases and 10 public validation cases, three confirmation
repeats, 4.8-second search and 4.95-second process limit, 1 CPU/512 MiB per case,
and six case workers. The Pro run retains the shared exclusive evaluation lock
with v4 Pro; this changes elapsed scheduling time, not per-solver resources.

This is an explicitly documented mid-run budget extension, not a fresh run
whose 256-call budget was fixed from its beginning. Independent stochastic
search trajectories and execution dates still differ. Same configuration does
not imply equal total tokens or a statistically conclusive model comparison.

After migration, use `python -B scripts/v5_pro_256.py` to resume with
`AAD_API_KEY` supplied in memory. Do not restart the old version-5 branch of
`pro64_experiments.py` or use `resume_paused_20260925.py` for this migrated run.
The normal pipeline finishes public selection/freezing, source audit and the
official Rust-generated 1000-case terminal evaluation, reusing the matched
kusano baseline. It never supplies private cases to the evolution loop.

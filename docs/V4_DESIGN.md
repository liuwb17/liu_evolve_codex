## 从 v3 证据得到的改动

| 观察 | v4 实际实现 |
|---|---|
| Flash 256次请求中80次响应无效，53次达到长度上限 | 设计和实现分两次请求；设计上限4096 tokens，完整源码24576，局部编辑12288。仅设计启用低强度 thinking；代码生成禁用 thinking，不再把整份源码包成大型 JSON。finish_reason 必须为 stop，完整源码必须有结束标记。失败仍计费/计数，不伪造修复截断内容。 |
| 初代8次尝试中很多未得到程序 | 目标4个有效初代谱系，最多12次初代尝试；没有有效程序时到达上限就明确失败，不无限重试。初代不输入任何旧解法。 |
| 多机制同时改变难以知道提升来源 | 局部、性能优化及交叉均仅允许一个唯一锚点的精确替换，并绑定父代哈希；先写可检验假设，再实现。大改另走完整源码重设计。一个连续编辑仍可能包含多种语义改动，框架不能自动证明机制纯度。 |
| 家族名由模型自由填写，不能可靠代表多样性 | 按独立初代的真实谱系维护岛屿，轮流选择岛屿父代。每12个实验提供独立重启机会；交叉从其他岛屿选择逐例互补供体。 |
| 固定算子循环，不考虑成功率/开销 | 对 local/performance/crossover/redesign 使用按实际全局收益和token成本计算的UCB选择。每种先探索一次，失败收益为0。独立初代和修复单独调度。 |
| 单次计时分数会波动；微小差异触发换优 | 合法候选先完整40例；有希望的候选做3次独立缓存重复。每例先平均重复结果，再进行逐例配对bootstrap。训练换优需平均增益>0.1M且区间下界>0；不把120次执行冒充120个独立实例。每5个实验额外复核一次，缓解首轮噪声漏筛。 |
| 验证仅约780分差异就换掉训练优胜者 | 至多3个候选，在10例验证上各重复3次。验证换优要求>0.2M和配对下界>0，并按挑战者数调整alpha；否则保留训练阶段稳定优胜者。若优胜者验证非法，明确失败，不悄悄替换。 |
| 参数未接入代码，以及同源码新元数据被丢弃 | v4不自动套用v3末尾64组参数流程。局部数值修改可以通过普通单改动演化；另提供参数输出影响检测函数，默认输出不稳定或端点改变没有影响时拒绝准入。它只是一道必要检查，不证明参数语义正确；尚未接入自动数值优化器。 |

不能把 v3 失败全归因于框架：模型能力、调用配置、只有50例公共数据和算法本身同样可能限制性能。以上是针对已观察故障的工程改进，不是因果证明。

## 请求和代码协议

设计响应只含 `hypothesis / mechanism / expected_effect / risk / test` 短字段。实现请求使用该设计；完整程序直接返回 C++17，末尾为 `// AAD_V4_COMPLETE`。局部编辑为一个 `{old,new}` 对，要求 old 在已知父代中唯一出现，按字面替换并重做编译与评测。控制器不手写矩形构造、退火或其他求解器逻辑。

**两阶段通常意味着每个候选两次API请求**，不会把128次调用宣传成128个候选。没有单独隐藏的修复请求或路由探测调用。客户端在HTTP前记录请求和预算；保存实际返回模型名、指纹、usage、耗时、结束原因、响应全文。密钥不落盘。未知用量按保守预留计入预算，已报告用量替代预留；预算不是精确账单金额。

设计与代码分离遵循官方 thinking 开关，而不依赖温度影响思考过程。依据：[DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)，核查日期2026-09-23。模型名继续使用用户指定的 `deepseek-flash`。

## 数据、评测与限制

仅载入官方公共50例，固定40训练/10最终选型，单个候选6例短预算合法性检查、40例4.8秒完整评测。短预算不按成绩淘汰。容器沿用已验证的无网络、只读、非root、1 CPU/512 MiB约束，硬限4.95秒；镜像和关键实现文件哈希记录进协议，恢复时不能静默改动。

重复运行用不同缓存目录，防止“复测”直接命中同一条缓存。它测量墙钟预算导致的执行波动，不改变求解器随机种子。配对bootstrap和固定最小增益是保守工程门槛，不是多轮自适应选择下严格有效的显著性保证；40/10小样本的泛化风险依然存在。

验证启动前持久化关闭开发的状态，不再允许训练或调用模型。先冻结，再显式调用私有终测入口；该入口先检查冻结和源码审计，之后才打开官方种子。既有1000例已经被先前实验观察，今后成绩应标为该已知基准上的终测，不能宣称全研究层面的完全盲测。v4模型不会接收那些私有输入、失败案例或人类源码。

## 操作

```powershell
# 可选：基础设施测试，不调用LLM，不作为算法种子
python -B scripts/v4_sandbox_smoke.py

# 真正付费运行，必须使用新目录；这次交付未执行此命令
python -B scripts/v4_search.py --run-dir runs/v4_flash_trial --calls 128 --token-budget 8000000 --ask-key

# 同配置续跑；STOP_AFTER_CURRENT 在实验边界停止
python -B scripts/v4_search.py --run-dir runs/v4_flash_trial --calls 128 --token-budget 8000000 --ask-key --resume

# 只进行验证与冻结，不再调用API，也不需要密钥
python -B scripts/v4_search.py --run-dir runs/v4_flash_trial --calls 128 --token-budget 8000000 --resume --finalize
python -B scripts/v4_audit.py --run-dir runs/v4_flash_trial

# 显式终测，使用官方种子及原版Rust工具，复用已测kusano对照
python -B scripts/v4_system_test.py --run-dir runs/v4_flash_trial --output runs/v4_flash_trial_system1000
```

源码入口：`aad/v4_engine.py`、`aad/v4_provider.py`、`aad/v4_protocol.py`。故障和复测记录在运行目录 `state.json`，原始请求在 `llm/`，每轮候选在 `candidates/`。恢复成功响应时不会再付费重发；失败请求按记录保留。当前为单控制器设计，不允许多个写进程同时操作一个运行目录。

## 建议的验收，而非预先宣布胜利

先开展小额真实API试运行，核对完整响应率、有效初代数、每个有效候选tokens及新框架开销，再决定扩大预算。不要只看最高训练分。若要归因于某一项框架改进，应以相同模型和预算做多轮独立运行与消融；本次未执行这些付费比较。
